# RediensIAM route reference

Every route the application maps: **190 controller actions** across 12 controllers, plus five
non-controller endpoints and two SPA fallbacks.

Generated by reading `src/Controllers/*.cs` and cross-checked against
`src/Program.cs` and `deploy/rediensiam/templates/ingress.yaml`. Method and type names are cited
rather than line numbers, because `src/Controllers/` moves.

For *how* to call these — bodies, the `snake_case` rule, the `aud` contract, migration notes — read
[`INTEGRATION.md`](INTEGRATION.md). This file answers "what exists, who may call it, and can I
reach it from where I am".

---

## How to read the tables

### Authority

| Marking | Meaning |
|---|---|
| **anonymous** | no bearer token required |
| **any user** | any valid bearer token (the request is about the caller's own account) |
| **ProjectAdmin** / **OrgAdmin** / **SuperAdmin** | a `GrantedLevel` at least this privileged, **re-verified against Keto on every request** (30 s cache) |
| **service account** | the caller must be a service account (PAT, or a `sa_`-prefixed `client_credentials` token). A management level is not the question being asked |

`ManagementLevel` is ordered `SuperAdmin = 1, OrgAdmin = 2, ProjectAdmin = 3` — **lower is more
privileged**, and a check is `granted <= required`. So a SuperAdmin satisfies a ProjectAdmin
requirement, not the other way round.

The level in the table is the **class-level floor**. Several controllers apply a stricter
per-object check on top of it, noted per group.

### Reachability

| Marking | Meaning |
|---|---|
| **public** | served on the public hostname (and on the admin hostname) |
| **admin-only** | the ingress returns **403** for this prefix on the public hostname |

Reachability is an **ingress** property, not an application one. `app.MapControllers()` maps every
route on both the `:5000` and `:5001` listeners; only Swagger and `/metrics` are port-gated. The
public host carries a second Ingress whose Traefik middleware is an `ipAllowList` of
`255.255.255.255/32` — an unconditional deny — over the longer path prefixes
(`deploy/rediensiam/templates/ingress.yaml:111-169`):

```yaml
adminOnlyPaths: [/admin, /console, /org, /project, /service-accounts]
```

`/auth`, `/account` and `/api` are deliberately absent. **This is why `/api/manage/*` is public and
`/admin/*` is not**, even though they are the same controller — a machine caller needs a route that
does not depend on reaching the admin ingress.

If `adminOnlyPaths` is emptied, or the deployment does not use this chart, everything below is
reachable everywhere and the only remaining controls are the audience gate and the Keto re-check.

## The one-controller-two-prefixes rule

Three controllers carry two `[Route]` attributes:

| Controller | Prefixes | Level |
|---|---|---|
| `SystemAdminController` | `/admin` · `/api/manage` | SuperAdmin |
| `SystemHealthController` | `/admin/system` · `/api/manage/system` | SuperAdmin |
| `AdminWebhookController` | `/admin/webhooks` · `/api/manage/webhooks` | SuperAdmin |
| `ImpersonationController` | `/admin/impersonate` · `/api/manage/impersonate` | SuperAdmin **and** a service-account caller |

These are **the same action**, not two implementations: one token check, one audience gate, one
live Keto re-check, whichever prefix you used. The tables below therefore list each route once,
under its `/admin*` form, with the alias implied. `/api/manage/x` exists for every `/admin/x` in
the `SystemAdminController` table, and likewise for the other two.

The pairing is asserted by `ApiSurfaceManagedParityTests`, so it cannot drift.

**Not aliased:** `/service-accounts`, `/org` and `/project`. `/service-accounts` in particular runs
its own per-object authorisation, and a route alias there would be a place for that check to be
skipped.

## Non-controller endpoints

| Method | Path | Authority | Reachable | Source |
|---|---|---|---|---|
| GET | `/health` | anonymous | public | `Program.cs:399` (`MapHealthChecks`) — liveness; `Predicate = _ => false`, so it runs no check and answers as long as the process is up |
| GET | `/health/ready` | anonymous | public | `Program.cs:400` — readiness; runs only the checks tagged `ready` |
| GET | `/console/config` | anonymous | admin-only | `Program.cs:429` — a minimal endpoint, deliberately outside `SystemAdminController` so the SPA can bootstrap its OIDC config. Returns `hydra_url`, `client_id`, `redirect_uri` and the running assembly's `version` |
| GET | `/metrics` | anonymous | admin **port** only (endpoint filter on `Connection.LocalPort`) | `Program.cs:448` — Prometheus scrape. Not `RequireHost`: host filtering strips the port before comparing, so a caller on the public port could scrape it by sending the admin port in a `Host` header |
| GET | `/swagger`, `/swagger/v1/swagger.json` | anonymous | admin **port** only | `Program.cs:385-389` |

Plus two SPA fallbacks: `MapFallback("/console/{**path}")` serves the admin console's
`index.html` (`Program.cs:454`), and `MapFallbackToFile("index.html")` sends everything else to the
login SPA (`Program.cs:461`). Browser navigations carry no `Authorization` header and must load —
which is why the admin bearer check keys on *"did this resolve to a controller action"* rather than
on the header being absent.

The login SPA's own routes are client-side and reach the server only through that second fallback;
they are not application routes and are not listed here. One of them matters to this table:
**`/logout` is a page, not an endpoint.** It drives the `GET /auth/logout` · `POST /auth/logout`
pair below — `hydra.urls.logout` used to point straight at the controller, which answers JSON, so
the browser landed on a raw `{"logout_challenge":"…"}` body and nothing ever accepted the request.

**The console is served at `/console/`, not `/admin/`, and that is deliberate.** `/admin/*` is the
management API alone — every path under it in this file is a `SystemAdminController`,
`SystemHealthController` or `AdminWebhookController` action, and nothing under it serves HTML.

The console did live there, and the management API owns that prefix: `SystemHealthController` is
mounted on `admin/system`, which is exactly where the console's System scope lives. Thirty of the
console's forty-nine pages answered a browser with a bare 401 before a byte of the SPA had loaded —
no bookmark, no refresh, no pasted link. Giving the human surface its own prefix removes the
collision by construction instead of exempting one route from the gate. `Roles.ConsoleBasePath` is
the single place the prefix is written; the server fallback, the OIDC `redirect_uri` handed out by
`/console/config` and the router all read it — the last through Vite's `base` — so the bundle, the
router and this fallback cannot drift apart.

`app.adminPath` in the chart is plumbed to an env var and a database column and is **read by
nothing**. It never controlled this prefix.

## `/api` — IntrospectionController · 2 routes

**service account · public.** This is the resource-server surface. It is the sole entry in
`GatewayAuthMiddleware.SelfGatedControllers`: it gates on *being a service account*, which is a
different question from a management level, so it is exempt from the default-deny that covers the
rest of `/api`.

| Method | Path | Action | Content type |
|---|---|---|---|
| POST | `/api/introspect` | `Introspect` | `application/x-www-form-urlencoded` (RFC 7662) |
| POST | `/api/authorize` | `Authorize` | `application/json` |

`project_id` is **mandatory** on both (`400 {"error":"project_id_required"}`). A plain user token is refused with
`403 service_account_required` — otherwise the endpoint is an oracle any bearer could use to probe
token validity.

Read [`INTEGRATION.md`](INTEGRATION.md#introspection--the-backend-path) before calling these; the
`aud` requirement is a breaking change with no grace period.
